## 画板基准

| 项 | 值 |
|----|-----|
| **主画板** | **1920 × 1080**（16:9） |
| 用途 | 目录 / 工作台等桌面示意与定稿均以此为基准出图、对齐 |
| 备注 | 实现仍是响应式/`100vh`；小屏（如 1366、1440）定稿后再做抽查，不另开主画板 |

## 改图纪律（必须遵守）

1. **你只说改某一控件时：只改那一处**，其余布局/文案/列表数据保持上一版基准不变。  
2. **禁止**为改一个按钮就「整页重新生成」导致页面大变脸（AI 全页重绘极易漂移）。  
3. 小改优先：文字说明规格 / 局部标注 / 可编辑 HTML 稿；只有 **整页改版** 才全页出新图。  
4. 目录页当前基准：**`current/01-catalog-latest.jpg`**（最新讨论稿，**尚未定稿**）。后续小改必须相对该文件。  
5. **小改出图必须把基准图作为参考图喂给模型**（`reference_image_paths`），并写明「只改某某」；禁止无参考图整页盲生。  
6. 你说「定稿」后再移入 `approved/`；在此之前不要按稿改前端。

## 工作方式（必须遵守）

1. **功能面**：以**现已落地的能力**为准（见 `docs/UI-POLISH.md` / `REMAINING-GAPS.md`），**基本不再大改功能**；不借设计讨论加需求。  
2. **本目录只服务**：产品交互、信息架构、视觉与排版的**优化讨论**。  
3. **节奏**：**慢慢讨论** → 你点头写入 [`approved/`](./approved/) **定稿** → **再**改代码打磨。  
4. **未定稿前**：可以出图、改 `current/`、改文档结论草案；**不要**按未定稿示意大改前端。  
5. **讨论态度（你要求）：** 不能「你说什么都好」。若说法有漏洞、和现网能力冲突、伤可用性/一致性，或有更优方案，**必须直接提出反对与建议**；只有经得起推敲的才算好，再写入定稿。  
6. **体验总原则：** 有用、合理、无冗余、简约、体验要好。**简约 ≠ 砍功能**：默认安静、入口不重复；现网能力可收纳，不借设计删除。细则见 `docs/UI-POLISH.md` 产品立场。  
7. **有理有据：** 讨论与建议须可核对（现网 / 企微 `wecom` 材料 / 点名对标产品的具体交互），**禁止瞎编「最佳实践」**。对标以智能表/多维表类为主（企微、飞书多维、Notion DB、Airtable 等），说清学哪一点、是否适合本产品双路由与自有账号边界。

## 已定结论（优化时勿回退）

| 项 | 结论 |
|----|------|
| 路由 | **维持双路由**：目录 `/`（`HomeView`）与工作台 `/workspaces/:ws/bases/:base`（`BaseShellView`）。**不做**单壳 `/?ws=&base=` 合并。 |
| 成员 | **工作区级**能力；入口放在工作区语境（标题旁 / 工作区 ⋯ / 工作区▾），**不放全局顶栏**右上。 |
| 顶栏（目录） | 宜保留全局：消息、账号；勿堆工作区专属入口。 |
| 顶栏（工作台） | 表级：评论、内容权限、公开视图、自动化、导出等；回目录用面包屑。 |
| 目录列表元数据 | **不展示**列数/行数；优先名称、描述、更新时间。 |
| 暂缓 | 断网/离线/实时协作/同步（见 `docs/REMAINING-GAPS.md`）。 |
