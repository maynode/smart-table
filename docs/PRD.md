# 产品需求文档（PRD）

## 1. 定位

企业私有化部署的「智能表格 + 仪表盘」：以企业微信智能表格为唯一对标，补齐其在序列号领取场景的三个硬伤：

1. **成功页字段是动态的**：提交成功后展示的序列号来自自动化占用码库后的真实结果，而不是表单里预先填的值。
2. **查找记录默认只取 1 条**：`FindRecords.limit` 缺省值为 `1`，与「领取一个」的业务语义一致，避免误改全部记录。
3. **并发领取原子安全**：同一码不会被两个提交同时领走；码尽时明确失败且不产生脏写。

不追求 CRDT、可编辑公开链接、多地域双活；不做飞书/Airtable 对标；短信 OTP 不在范围内。

## 2. 用户与场景

| 角色 | 诉求 |
| --- | --- |
| 活动运营 | 建收集表单、配置码库与「领取序列号」自动化、把二维码发到群里 |
| 领取人 | 打开分享链接，填手机号，立即在成功页看到自己的序列号 |
| 管理员 | 查看领取流水、码库占用情况、自动化运行日志与失败原因 |
| IT/运维 | 内网一键部署，数据不出企业，可备份、可扩容、可审计 |

核心闭环：

```
分享链接 → 公开表单填写 → 提交（同一事务）
  → 触发「新增记录」自动化 → 查找 1 条未领码 → 修改为已领（SKIP LOCKED）
  → 合并 formCells ∪ stepOutputs → 渲染成功页（含序列号）
  → 写领取流水/自动化运行日志
```

## 3. 功能范围（Phase 0–1）

- 账号与工作区：注册/登录、成员与角色（owner/admin/editor/viewer）。
- Base / 工作表 / 字段：27 种字段类型契约；字段增改、隐藏、必填。
- 记录 CRUD：游标分页、乐观锁 `expectedVersion`、批量导入导出（Excel）。
- 视图：筛选、分组、排序、行高、填色、条件格式；千万行 Canvas 网格。
- 收集表单：公开分享 token、二维码、封面、显示条件、必填校验、IP+token 限流、关闭/过期 403。
- 自动化：新增/更新/定时触发；六种动作（查找、新增、修改、发消息、建群、拉群成员）；运行日志。
- 成功页：动态变量合并、HTML 模板、预览接口、未找到变量保留。
- 仪表盘：图表、指标卡、定时推送（Task 18）。
- 权限：内容权限、跨工作区分享、公开只读（Task 17/19/24/25）。
- 开放能力：Open API、Webhook、企业微信 OAuth/通知适配（Task 20/22）。
- 运维：Compose/K8s、OpenTelemetry、审计与配额、同步（Task 13/14/21/23）。

## 4. 非功能指标

| 指标 | 目标 |
| --- | --- |
| 并发领码 | 100 并发 / 50 码，恰好 50 成功、50 明确失败，零重复 |
| 提交扩展性 | 架构可扩展到百万级并发表单提交（队列 + 无状态 API + 连接池） |
| 表格规模 | 千万行不卡顿（视口裁剪 + 均匀轴 O(1) 定位） |
| 安全 | 密码 argon2id；公开接口限流；成功页变量 HTML 转义；租户隔离 |
| 私有化 | 全部组件可离线镜像；无公网依赖 |

## 6. 关键产品决策

- 成功页变量命名使用**字段名**（如 `{{序列号}}`），自动化输出覆盖表单同名字段。
- 码尽返回 `409`，文案「序列号已领取完毕，请稍后再试」；整个提交事务回滚，不写表单记录、不写领取流水。
- 同手机号默认不可重复领取（可按表单关闭）；校验在事务内用 advisory lock 串行化，避免并发绕过。
- 自动化「查找」步骤默认 limit=1；需要批量时必须显式设置 limit。
- 自动化「找不到」默认继续执行；可配置为终止，终止时本次运行标记 `skipped`。
