# 通用智能表格 — 产品与技术方案

> 独立产品方案文档。目标对齐 Airtable / 飞书多维表能力全集；分期落地，但产品定位是完整平台，而非单场景工具。

---

## 1. 定位

| 项 | 说明 |
|----|------|
| 产品形态 | 云端智能表格（多维表）SaaS |
| 主对标 | **Airtable**（能力天花板）、**飞书多维表格**（国内体验与协作习惯） |
| 参考 | 企业微信智能表格（作能力短板与差异对照，不作主对标） |
| 核心差异（相对企微短板） | ① 自动化支持「只处理 N 条（默认 1）」② 表单成功页可展示动态字段（如刚分配的序列号）③ 并发占码原子安全 |

**子集关系：**  
「表格 + 表单 + 自动化 + 成功页动态结果」（覆盖码库发放等场景）是底座；完整平台在其上扩展权限、多视图、仪表盘、开放 API、插件生态。

## 2. 竞品对标

通用智能表格只深挖两家；其余产品不作全面摸底。

| 角色 | 产品 | 用途 |
|------|------|------|
| 主对标 | Airtable | 定能力上限与信息架构：字段体系、多视图、关联/公式、自动化、API、模板生态 |
| 主对标 | 飞书多维表格 | 定国内可用性：表单、自动化、权限、协作习惯、免费/付费边界 |
| 参考 | 企业微信智能表格 | 已知痛点对照（成功页难出动态码、查找易一次改多条、外部用户触达弱）；不作为能力全集标杆 |

**调研截图清单（两家各截同一套）：**

1. 字段类型列表  
2. 视图切换（表格 / 看板 / 日历 / 画廊 / 表单）  
3. 表单成功页（能否插入字段变量）  
4. 自动化：查找记录、修改记录、是否支持「只处理 1 条」  
5. 权限设置（Base / 表 / 字段 / 记录）  
6. API / Webhook 入口  
7. 该功能免费或收费标识（价目或灰显即可）  

### 2.1 开源参照（非产品对标）

英文品类常见说法：**Smart Table / Smart Sheet**；对外更准确可用 **No-code Database** / **Spreadsheet Database**（Airtable-like）。

以下项目作技术与体验参照，**不替代** Airtable / 飞书主对标；自有 SaaS 一般不直接「改皮上线」，成功页变量、`limit=1` 占码等差异仍需自建。

| 项目 | 协议 | 要点 |
|------|------|------|
| [Baserow](https://baserow.io/) | MIT | 开源程度最好；表+视图+表单+API；社区版部分能力在付费；**二次开发首选候选** |
| [Teable](https://teable.io/) | AGPL | 体验接近 Airtable；实时协作、仪表盘强；自动化相对弱；商用注意 AGPL |
| [NocoDB](https://nocodb.com/) | Sustainable Use（非严格开源） | 可挂接已有 MySQL/Postgres；功能全；闭源商用需看授权 |
| [APITable](https://github.com/apitable/apitable) | AGPL | 偏协作应用；国内团队背景；体量大 |
| [Grist](https://www.getgrist.com/) | Apache-2.0 | 偏可编程表格 + Python 公式，不像飞书多维表 |
| [Mathesar](https://mathesar.org/) | GPL-3.0 | Postgres 表格 UI，更像 DB 前端 |

**选用倾向：** 真开源可商用改造 → Baserow；体验最像 Airtable → Teable；接现有库 → NocoDB（注意协议）。

## 3. 能力地图

### 3.1 核心底座

| 模块 | 能力 |
|------|------|
| 工作区 / Base | 多工作区、多 Base、多数据表、文件夹、回收站、模板 |
| 字段类型 | 文本、数字、单选/多选、日期时间、人员、附件、关联、查找引用、公式、自动编号、手机号、勾选、链接等 |
| 视图 | 表格、看板、日历、画廊、表单视图；筛选 / 分组 / 排序 / 条件颜色 |
| 收集表单 | 对外分享链接/二维码；字段显隐与必填；提交次数限制；**成功页自定义文案与字段变量**；再填一次 |
| 自动化 | 触发（新增/更新/定时）；条件；动作（查找、修改、新增、发通知、Webhook）；**查找结果可 `limit`（默认 1）**；修改可绑定「上一步查找结果」；运行日志 |

### 3.2 平台能力

| 模块 | 能力 |
|------|------|
| 权限与协作 | Base / 表 / 字段 / 记录级权限；角色（Owner / Editor / Viewer）；对外表单匿名或登录 |
| 仪表盘 | 数字卡、柱状/折线/饼图、指标筛选 |
| 开放能力 | REST API、出站 Webhook、Excel 导入导出 |
| 审计与用量 | 操作审计、自动化运行次数、存储配额 |
| 登录与集成（可选） | 账号密码 / 手机；企业微信、微信 OAuth |
| 生态 | 模板市场、插件 SDK |

### 3.3 官方场景模板（验收用）

至少内置 **「序列号 / 兑换码发放」** 模板，用于证明底座过关：

- 同一入口码，从码库领取唯一序列号  
- 提交成功页直接展示该序列号  
- 一次提交只占用一条未领码  
- 可配置：同手机号不可重复领、码发完提示

## 4. 信息架构

```
Workspace（工作区）
 └── Base（应用/库）
      ├── Sheet（数据表）× N
      │    ├── Field（字段定义）
      │    ├── Record（行）
      │    └── View（视图）
      ├── Form（收集表单，绑定某 Sheet）
      ├── Automation（自动化）
      └── Dashboard（仪表盘）
```

## 5. 技术架构

### 5.1 推荐选型

| 层 | 选型 |
|----|------|
| 前端 | Vue 3 + TypeScript + Vite；大表用虚拟滚动 / Canvas 网格 |
| 后端 | NestJS（Node.js）+ TypeScript |
| 主库 | PostgreSQL（元数据规范化 + 行数据 JSONB） |
| 缓存 / 队列 | Redis + BullMQ（自动化异步执行） |
| 文件 | S3 兼容对象存储 |
| 实时（可后置） | WebSocket / SSE |
| 部署 | Docker；单区域起步 |

仓库建议 monorepo：`apps/web`、`apps/api`、`packages/shared`（字段类型、公式 AST、校验）。

### 5.2 核心模型（概念）

- **Record**：`{ id, sheetId, cells: Record<fieldId, value>, version }`  
- **Form**：字段映射 + `successPage` 模板（支持 `{{fieldId}}` 变量）  
- **Automation**：`trigger` + `steps[]`  
  - `FindRecords`：`filter` + **`limit`（默认 1）**  
  - `UpdateRecords`：目标可为「上一步查找结果」，禁止默认「全表满足条件就全改」  
- **码库类场景**：事务内 `SELECT … FOR UPDATE SKIP LOCKED`（或等价乐观锁），保证并发下一人一码  

### 5.3 表单提交与成功页（关键链路）

```
用户提交表单
  → API 写入表单对应记录
  → 触发自动化（短流程可同步等待；长流程异步 + 成功页轮询）
  → 查找未领码（limit=1）并事务占用
  → 回写序列号等到表单记录
  → 成功页渲染模板（展示 {{分配序列号}} 等）
```

超时策略：成功页提示「处理中，请刷新」；后台仍可完成写回，用户刷新或查询可见。

### 5.4 自动化执行示意

```
Trigger: Sheet 新增记录（且手机号不为空）
  → FindRecords(码库, 状态=未领, limit=1)  未找到则终止
  → UpdateRecords(查找结果, 状态=已领, 手机号=触发记录.手机号)
  → UpdateRecords(触发记录, 分配序列号=查找结果.序列号)
  → Notify（可选：邮件/短信/站内；成功页已展示则通知为增强）
```

## 6. 分期计划

产品目标是全集；工程按阶段交付，每阶段可发布可用版本。

### Phase 0 — 骨架（约 2–3 周）

- 账号、工作区、Base、Sheet CRUD  
- 字段 CRUD、表格视图读写  
- Excel 导入导出  
- Base 成员角色：Owner / Editor / Viewer  

### Phase 1 — 核心底座（约 4–6 周）【必须过关】

- 收集表单分享（链接 / 二维码）  
- **成功页自定义 + 字段变量**  
- 自动化：新增触发、查找（limit=1）、修改查找结果、运行日志  
- 官方模板「序列号发放」+ E2E  
- 字段唯一约束（如手机号）；可选短信验证码（对接云厂商，按条计费，默认可关）  

**Phase 1 验收**

| 项 | 标准 |
|----|------|
| 一领一码 | 100 条未领时，提交 1 次只变 1 条已领 |
| 成功页 | 正文直接显示本次序列号（不依赖站内信） |
| 并发 | 两人同时提交不会领到同一码 |
| 码发完 | 成功页明确提示，无脏写 |
| 日志 | 可查触发记录、匹配行、写回字段 |

### Phase 2 — 多维表体验（约 4–6 周）

- 看板 / 日历 / 画廊视图  
- 关联字段、查找引用、公式（受限函数集）  
- 筛选 / 分组 / 排序持久化  
- 附件字段  

### Phase 3 — 平台能力（约 6–8 周）

- 字段级、记录级权限  
- 仪表盘  
- REST API + Webhook  
- 审计日志、用量配额  

### Phase 4 — 生态与增强

- 模板市场、插件 SDK  
- 企业微信 / 飞书登录与通讯录（可选）  
- 性能：十万行级、自动化吞吐、可选实时协作

## 7. 非功能要求

| 类别 | 要求 |
|------|------|
| 安全 | 租户数据隔离；表单外链可设密码 / 有效期；附件鉴权 |
| 可靠 | 自动化至少一次投递 + 幂等键；占码必须事务化 |
| 可观测 | 自动化运行日志、失败告警、API 调用指标 |
| 合规 | 手机号等个信息明示用途；短信需用户同意 |

---

## 8. 明确不做（首期）

- 一上来做复杂 CRDT 多人实时编辑（可后置）  
- 插件市场与第三方应用商店（Phase 4）  
- 多区域多活（先单区域）

## 10. 总结

- 做 **完整智能表格平台**，不是只做领码小工具。  
- 主对标 **Airtable + 飞书多维表格**；**企业微信智能表格仅作参考**（短板与差异对照）。  
- **底座必须先解决**：一码一人的原子分配 + **成功页直接出码**。  
- 其余多视图、仪表盘、API、插件按 Phase 2–4 推进，最终对齐 Airtable 级能力全集。
