# 全站响应式适配设计（移动 / 平板 / PC）

> 日期：2026-10-31  
> 状态：**已批准**（2026-10-31 审查后开工）  
> 范围：`apps/web` 全部用户可见面；不新开原生 App  

### 审查补丁（开工前锁定）

- 登录、公开填表 `/fill/*`、公开视图 `/view/*`：**不显示**站外底栏。
- Phone 紧凑表默认技术选型：**DOM 横向滚动表**（非降级 Canvas），点格 → 全屏/底栏字段编辑器。
- 深链 query 约定：`face` ∈ `data|form|automation|dashboard|analysis`；`oid` = 当前对象 id；表单子模式 `formMode` ∈ `design|results`。

---

## 1. Intent / Why

产品功能主路径已收口；当前 UI **以桌面 Canvas / 固定侧栏为主**，手机与平板体验不齐。目标是在 **不砍能力、不降级交互品质** 的前提下，让同一 Web/PWA 在手机、平板、PC 上都达到业界智能表格类产品的最佳交互密度。

交付约定：**一次做完全部面再验收**，不以「先上壳层、复杂面以后再说」交差。

---

## 2. Goals / Non-goals / Anti-goals

### Goals

1. **三端能力对等**：登录、首页、通知、Base 壳、数据表（含视图/筛选排序分组/批量）、表单构建与公开填表、自动化、仪表盘、分析报告、分享/公开视图、成员、权限、管理后台、评论等，在手机/平板/PC 均可完成同等任务。
2. **交互按设备选最佳形态**（非简单缩放）：手机优先触控列表与全屏编辑器；平板触控网格；PC 保持现有 Canvas 生产力。
3. **统一断点与壳层契约**，消灭零散 `@media` 各自为政。
4. **PWA 可用**：安全区、触控目标、横竖屏可用；可安装壳继续可用。
5. **协同语义不变**：在线 OT/WS、离线 Outbox、Live Bus 行为与桌面一致；小屏只换呈现，不换协议。

### Non-goals

- 不做独立 iOS/Android 原生壳。
- 不做企微内嵌 SDK / 企微登录。
- 不做像素级复刻企微移动端 UI；对齐 **交互范式与任务可达**。
- 不为响应式重做服务端 API / schema（除非发现确缺移动专用端点——默认复用现有）。

### Anti-goals（做成这样算失败）

- 小屏把自动化 / 仪表盘 / 表单构建藏成「请用电脑」。
- 手机继续硬塞完整多列 Canvas 作为默认主路径。
- 「能点开但编辑体验残缺」（缺字段类型编辑器、缺批量、缺视图切换等）。
- 分波上线后长期留半残断点。

## 4. Breakpoints（builder 可微调 ±64px，语义不变）

| Token | 宽度 | 主形态 |
|-------|------|--------|
| `phone` | `< 768px` | 列表/卡片、底栏或全屏 sheet、单列堆叠 |
| `tablet` | `768px – 1099px` | 触控网格或双栏；抽屉代侧栏；工具条可折行 |
| `desktop` | `≥ 1100px` | 现有侧栏 + Canvas + 浮层工具 |

实现：统一 `useViewport()`（`matchMedia` + SSR 安全默认 `desktop`），禁止各面板私设冲突断点。遗留 `640/860/960/1100` 迁移到上述三档。

## 5. Information architecture

### 5.1 站外（未进 Base）

- **底栏**：首页 | 通知 | 我的。
- **「我的」（D7）**：当前用户资料/头像、账号安全相关入口、退出登录；具备管理员角色时出现「管理后台」。**不含**工作区成员管理——成员/邀请留在首页选中工作区后的入口（与工作区绑定，避免「我的」变成杂物间）。
- 首页工作区/表列表：卡片流；创建表、邀请成员走全屏或底部 sheet。
- 通知：全宽列表（已有 640 雏形，升到 phone 标准）。
- **管理页（D8）**：`/admin/*` 保留站外底栏；页内顶栏可返回首页/工作区。

### 5.2 站内 Base（`BaseShellView`）— 面优先（D6）

- **无站级底栏**（避免挤编辑区）。
- **顶栏**：返回（出 Base）| **当前对象名** | 关键操作 | 「更多」（含表设置/字段管理等结构入口，D5）。
- **面 Tab（对象大类，等权）**：数据 | 表单 | 自动化 | 仪表盘 | 分析。无权限的面 **隐藏**（不灰置唬人）。
- **侧栏 / 抽屉内容随 Tab 过滤**：
  - **数据**：sheets + 其下命名视图；选中 sheet/view 决定网格/列表数据源。
  - **表单**：该 Base 下表单列表；选中表单进构建。**「收集结果」挂在表单面**（选中某表单后的子模式或子 Tab：设计 | 结果），不塞进「数据」以免和业务表混淆。
  - **自动化**：自动化流程列表（取代仅顶栏抽屉；桌面亦可收敛为同模型）。
  - **仪表盘**：仪表盘列表。
  - **分析**：分析报告列表。
- 侧栏形态：phone → 抽屉；tablet → 可折叠抽屉或窄轨；desktop → 现宽度，但 **仍按当前 Tab 过滤**（桌面也可从「一棵巨树」收成「分类树」，降低认知负担；若桌面需「一次看全对象」可在抽屉顶提供「全部」开关——默认分类过滤）。
- 深链 / 刷新：URL（或既有 query）须能恢复 `face + objectId`（及表单的 design|results）；builder 定具体参数名。
- 评论、分享、权限、模板等 → **全屏 sheet / 抽屉**，禁止桌面 modal 在 phone 溢出裁切。

## 6. Surface specs

### 6.1 数据表（最高难度）

**Phone — 默认「列表」模式**

- 行 = 卡片：主字段标题 + 2～3 个摘要字段（来自视图列或 title 字段）。
- 顶工具：搜索、筛选/排序/分组（进全屏配置页）、视图切换、新增、多选。
- **点卡片** → **记录详情**全屏：字段纵向栈，复用现有字段编辑器语义（单选/人员/附件/公式只读等），提交走现有 commit / collab 路径。
- **点摘要字段芯片**（可选增强）→ 同字段聚焦编辑 sheet（少一步进详情）。
- 批量删除/改：多选模式 + 底栏操作条。
- 协同：详情顶显示锁/他人编辑提示；列表可用角标表示脏行（不要求 phone 画 peer cursor）。

**Phone — 「紧凑表」模式（可切换，非默认）**

- 水平滚动的简化表或降采样列；点格 → 底部/全屏字段编辑器（非桌面浮层定位）。
- 不要求千万行 Canvas 手势完全孪生；窗口加载 API 与桌面共用。

**Tablet**

- 默认触控网格：加大触控热区、列宽下限、惯性滚动；筛选等用右侧/底部抽屉。
- 可选左列表右详情（宽平板横屏）。

**Desktop**

- 保持 `GridPanel` + `CanvasGrid`；壳层仅做弹性与溢出修复。

**共享数据层（必须）**

- 列表/详情与 Canvas **共用** `BaseShellView` 的 records 窗口、query、commit、selection、live/collab 订阅。
- 新增组件建议落点：`RecordListView.vue`、`RecordDetailSheet.vue`；`GridPanel` 按 viewport 切换 stage，不复制业务状态。

### 6.2 表单构建（`FormBuilderPanel`）

- Phone：单列；字段列表为主；点字段进配置全屏；预览用「真机预览」全屏（可保留现 phone-frame 概念）。
- 显示条件、成功页、分享：各自全屏向导，禁止三栏并排。

### 6.3 公开填表（`FormFillView`）

- 已接近手机优先；补齐 safe-area、字号、错误滚动进视口、附件/拍照 `capture`。
- 横屏仍单列可读宽度。

### 6.4 自动化（`AutomationPanel` / `AutomationEditor`）

- Phone：流程列表 → 点进编辑器全屏；步骤时间线纵向；条件/动作配置为逐步 sheet。
- 变量插入、运行日志：全屏；不砍步骤类型。

### 6.5 仪表盘（`DashboardPanel`）

- Phone：单列卡片栈；点图进「图详情/配置」全屏；布局编辑用长按排序或显式「调整布局」模式（避免误拖）。
- Tablet：2 列 bento；Desktop：现 12 列。
- Agent/分析对话：底栏输入 + 消息列表，不挡图表阅读。

### 6.6 公开视图（`PublicViewView`）

- 表数据：与登录态 phone 列表同源交互（只读或按 token 权限可写）。
- 禁止「仅横向滚动宽表」作为 phone 唯一形态。

### 6.7 首页 / 登录 / 通知 / 管理后台

- 登录：单列、大触控、键盘不挡主按钮。
- 首页：统一到 phone/tablet 断点（替换现 860 特判）。
- 管理三页：表格 → phone 卡片列表 + 详情/编辑 sheet；筛选工具条折行。

### 6.8 AI 格内组件等

- Phone 列表/详情内嵌与桌面单元格同等 bridge；详情内给足高度；不回到「仅 PC 可用」。

## 7. Design system constraints（体验底线）

- 触控目标 ≥ 44×44 CSS px；列表行高舒适可读。
- `viewport-fit=cover` + `env(safe-area-inset-*)` 用于底栏与全屏 sheet。
- 模态：phone 优先 **全屏 sheet**（圆角顶 + 拖拽关闭可选）；禁止超小居中弹窗堆表单。
- 动效：面切换与 sheet 进出有明确过渡；不为动效牺牲可点性。
- 可访问：焦点可见；关键操作不只依赖 hover。
- 视觉：沿用现有品牌绿与壳层语言，不借机换肤；禁止为「移动风」引入无关设计体系。

---

## 8. Engineering constraints

- 包：`apps/web`；共享逻辑优先抽 composable，避免复制 commit。
- 测试：关键面 Playwright 增加 **手机视口** 用例（至少：壳层进出 Base、列表改格提交、填表提交、自动化打开编辑器、仪表盘点开配置）；现有桌面 e2e 不得红。
- 性能：phone 列表虚拟化（长表）；禁止为响应式关掉窗口加载。
- 文档：实施后更新 `docs/UI-POLISH.md` 或新增 `docs/RESPONSIVE.md` 断点契约；不把本设计当成「可接受缺口」清单。
- 仍遵守：不做企微登录；协同主路径不变（`docs/COLLAB.md`）。

## 9. Acceptance（整包门禁）

下列全部在 **真实手机宽度（≤390）与平板（768–1024）与桌面** 手工 + 自动化抽检通过才算完成：

1. 底栏/表内顶栏切换正确；无双重底栏挤内容。
2. 数据：列表浏览、详情改各主要字段类型、筛选排序视图、新增/删除/批量，与桌面数据一致；**并**能完成新增字段或改字段选项（结构能力，D5）。
3. 紧凑表可切换且可编辑至少文本/单选。
4. 表单：构建主路径 + 「收集结果」在表单面可达 + 公开填表全流程。
5. 自动化：从自动化面列表进入，创建或编辑至少一条主路径跑通。
6. 仪表盘查看与改一图配置；分析面可打开一份报告。
7. 通知、分享/公开视图可达；**成员/邀请从首页工作区进入**可完成；权限入口可操作。
8. 管理页核心 CRUD 在 phone 可完成，且底栏仍在。
9. 横屏 phone 无不可滚动裁切；安全区无遮挡。
10. 桌面回归：Canvas 协同与现有 Playwright 绿；面 Tab + 分类侧栏不破坏既有深链习惯（或提供兼容重定向）。

## 10. Left to the builder

- `useViewport` 精确实现与 resize debounce。
- 列表摘要字段挑选算法（title 优先等）。
- 紧凑表用简化 DOM 表还是降级 Canvas 的技术选型（须满足触控编辑与窗口 API）。
- sheet 手势库自研或轻量依赖（若引入依赖须说明包体）。
- 具体 CSS 变量与组件拆分文件名（建议见 §6.1，可调整）。
- 测试用例文件切分与视觉回归是否上截图（默认以功能 e2e 为主）。
